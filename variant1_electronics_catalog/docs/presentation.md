# Презентация: Каталог электроники с быстрым поиском

## Слайд 1. Тема проекта
Вариант 1 — «Каталог электроники с быстрым поиском». Дисциплина: «Проектирование и применение NoSQL-технологий». Технология: MongoDB, Python.

## Слайд 2. Проблема и цель
Нужно хранить разные виды электроники с отличающимися характеристиками и быстро находить товары по названию, бренду, категории, цене и параметрам. Цель — реализовать прототип каталога.

## Слайд 3. Требования
CRUD-операции; поиск по названию и бренду; фильтрация по цене и характеристикам; средняя цена по категориям; подсчёт товаров; поиск товаров с низким остатком.

## Слайд 4. Почему MongoDB
Документная модель подходит для карточек с гибкими характеристиками. Вложенный объект `specs` позволяет хранить параметры ноутбуков, телевизоров, наушников и других категорий без одинаковой схемы для всех товаров.

## Слайд 5. Модель данных
Коллекция `products`. Поля: `_id`, `name`, `category`, `brand`, `price`, `stock`, `specs`. Один документ соответствует одной карточке товара. Используются синтетические данные.

## Слайд 6. Архитектура
Терминал → Python-приложение → PyMongo → MongoDB (`electronics_catalog.products`). Отдельный скрипт загружает данные; тесты проверяют тестовый набор.

## Слайд 7. Индексы
Составной индекс `category + price`, индекс `brand`, текстовый индекс `name + brand`. Метод `explain()` используется для изучения плана выполнения. Фактические замеры необходимо снять после запуска MongoDB.

## Слайд 8. Запросы
Поиск Apple; ноутбуки до 350 000 ₸; средняя цена по категориям; число товаров в категориях; низкий остаток; беспроводные наушники; фильтр Samsung по цене; `explain()`.

## Слайд 9. Тестирование и ограничения
Три теста проверяют объём набора, обязательные поля и заполненность категорий. Прототип учебный: нет веб-интерфейса, авторизации, оплаты и заказов.

## Слайд 10. Вывод
MongoDB обеспечивает гибкое хранение карточек и агрегирование данных. Реализованы базовые CRUD-операции, фильтры и индексы. Ссылка на GitHub: добавить после публикации.
